構造

3 部材が D.L. という単一の基準に乗る

座標系は X が法線直角方向(陸側 +X / 海側 −X)、Y が施設延長方向、Z が鉛直上向き。 Z = 0 を D.L.(基本水準面)に統一したことで、杭先端標高もタイロッド軸心標高も、 図面に書かれた数値がそのまま Z 座標になる。3 部材の標高を突き合わせる整合チェックが 常に同一基準で成立する。

部材が互いに追随する

前壁の挿入点は XData に tip_x/_y/_z の文字列と World 座標点(DxfCode 1011) を併記保存し、読み取り時は 1011 を優先する。1011 は AutoCAD が MOVE などの変換に自動追随させるため、 前壁を移動しても _Action は移動先で再生成される。タイロッド・控え杭は前壁 Handle から 位置を再計算するので、前壁の移動にも傾斜角 θ の変更にも整列位置が追随する。

基本的な流れ

  1. 前壁を作る。施工順位を指定すると、継手の要否と雌雄が順位から自動判定される(1 本目は +Y 側のみ、最終本は −Y 側のみ)。帳票があれば ImportCsv で壁全体を一括生成できる。
  2. 前壁を選んでタイロッドを置く。海側取付点 X は前壁の傾斜角と杭先端標高から自動算出されるため、指定するのは施設延長方向の Y だけでよい。
  3. 前壁を選んで控え杭を置く。span から整列位置が決まり、杭面間浄距離が負(干渉)ならエラー停止する。
  4. 数量を集計し、打設歩掛を積算する。工法は下表から 1 つを選ぶ。帳票があれば突合検証にかけられる。

控え杭は前壁と節が違う

控え杭は継手を持たない単独の鋼管杭であるため、SPQW_ANCHORPILE_Estimate は前壁の 4節 3-4.5(鋼矢板式)ではなく 4節 3-4.6(鋼杭式) に基づく。貫入抵抗値 R・ハンマ規格・ 打撃速度 Sb・溶接時間・準備時間・基準作業能力係数は両節で数値まで完全一致するため共有実装を再利用しているが、 1 本当り打撃時間 Tb の係数 K だけは異なる。前壁側の 3-4.5 は「直杭 K=1.0」しか 定義していないのに対し、控え杭側の 3-4.6 は「直杭 K=1.0・斜杭 K=1.2」を明記している。控え杭は 傾斜角を持つ用途(タイロッド軸線への整列)があるため、この斜杭補正は無視できない。本コマンドは 陸上打設のみ(3-4.6 の海上打設は未実装)。

取り込み

帳票からパラメータを流し込む

積算ソフトの出力を CSV UTF-8 形式で保存したものを読み込み、対話入力を省いて一括生成する。 列名は別名リスト(outer_d_mm / 外径 / D など)で解決し、 大文字小文字を無視する。個別列がない場合は「規格」列から φ800×12 L=20.0m LT75 のような表記を正規表現で抽出する。

1 行の不備で全体を止めない

数十行の帳票に 1 行だけ誤記があっても、エラー行を行番号付きで一覧表示したうえで、 残りの行は生成する。前壁の施工順位は「ファイルの総行数と出現順」を基準に自動採番するため、 途中の行が取り込みに失敗しても、残った行の先頭・末尾判定(=継手の要否)はずれない。

Dynamo

計算層は Zero Touch Node からも呼べる

Civil 3D 2025 同梱の Dynamo 3.3。カテゴリは SheetPileQuayWall.Plugin > Dynamo。 戻り値は [MultiReturn] で、辞書キーに日本語を用いる。 ジオメトリを扱わない純計算のため ProtoGeometry.dll は参照しない。

共通仕様

  • ノード検索で SpqwNodes. と入力すると 3 ノードが表示される。各引数がそのまま入力ポートになる
  • 未配線の入力ポートはデフォルト値で実行される。既定値のまま出力を確かめてから実データに置き換えられる(例外: CalcWeightedN はファイルパス必須)
  • 出力は [MultiReturn] の辞書で、日本語の辞書キーがそのまま出力ポート名になる。必要な項目だけ下流へ配線すればよい
  • 入力にリストを渡すと 1 要素ずつ自動で呼び出される(list-level 自動反復。下の例 1)
  • 入力は実務の呼び径慣行に合わせ mm 呼称(D_mm 等)で受け、ノード内部で直ちに m へ変換する。内部計算はすべて m
  • 入力不正はすべて ArgumentException を投げてノードを警告状態にする。不正値のまま計算は続けない
  • 打設歩掛(3 工法)のノードとジオメトリ生成ノードは未実装(後者は AutoCAD のトランザクションを伴い実機でしか検証できないため)

推奨ノード例

以下は 3 つとも Dynamo の標準機能(list-level 自動反復・既存の I/O ノード)を組み合わせただけで、 SpqwNodes 側に特別な対応は要らない。この開発環境には Dynamo 実行系が無いため グラフとしての動作は未検証であり、数値は Core 層(SectionProperties / QuayWallEstimate)を直接呼び出して算出した参考値である。

1. 候補径の比較検討 — 1 本の Code Block でまとめて計算する

Zero Touch Node は入力にリストを渡すと、Dynamo が自動で 1 要素ずつ関数を呼び出し、 結果をリストとして返す(list-level 自動反復)。候補となる外径を Code Block に 列挙するだけで、断面性能を横並びに比較できる。肉厚・全長・継手形式を 1 本の矢板と共通にして 比較すれば、径をひとつ上げたときの単位重量・有効幅の増分が一目でわかる。

2. 施工順位ごとの継手質量 — Core の判定ロジックをそのまま流用する

継手の要否・雌雄は施工順位から一意に決まる(PieceAssignment)。 Dynamo 側では List.Create と List.Count で「1 本目・中間・最終本」の 3 パターンを作り、CalcSection の断面性能と組み合わせれば、壁を構成する矢板の 総本数を変えるたびに手計算し直す必要がなくなる。 

 [Number] pieceCount = 10;  ── List.Count → 総本数
                                       │
   piece 1  ── 継手 +Y 側のみ(先頭)──┤
   piece 2〜9 ── 継手 両側 ───────────┼── 継手質量(1本あたり)= 側別質量の合計 × L_m
   piece 10 ── 継手 −Y 側のみ(末尾)──┘

1 本目・最終本は片側だけ、中間本は両側の継手を負担する。施設延長側で見ると 「継手接続数 = 総本数 − 1」であり、両者は独立に成立する等式として整合性チェックに使える (下の例 3 の 9 箇所と、この壁が 10 本であることを突き合わせられる)。

設計

Core と Plugin を分ける

計算層(Core)は AutoCAD に依存せず BCL のみを参照するため、WSL / Linux 上で 585 件のテストがそのまま走る。AutoCAD に依存するのは図形生成・XData・ コマンド定義だけで、こちらはスタブとリンクして構文・型検証まで行う。 

009_sheet-pile-quaywall/
├── src/SheetPileQuayWall.Core/     AutoCAD 非依存(BCL のみ)
│   ├── FrontWall/                  断面性能・継手・打設歩掛 3 工法
│   ├── TieRod/                     タイロッド計算・配置
│   ├── AnchorPile/                 控え杭の整列計算・打撃工法(4節3-4.6)
│   ├── Import/                     帳票 CSV 取り込み
│   ├── Geotech/                    柱状図から加重平均N値・一軸圧縮強度
│   ├── CrossMemberValidator.cs     部材間の整合チェック
│   └── QuayWallEstimate.cs         施設 1 件分の数量集計
└── src/SheetPileQuayWall.Plugin/   AutoCAD 依存
    ├── Commands/                   SPQW_* 19 コマンド
    ├── XData/                      キー=値 + 1011 併記
    └── Dynamo/SpqwNodes.cs         Zero Touch Node 3 個

守っている規約

  • using ディレクティブを書かず、型は完全修飾名で記述する(暗黙 using も無効)
  • 単位はメートル統一。mm は対話プロンプトと Dynamo 入力の呼称のみで、取得直後に m へ変換する
  • 部材 1 本につき Solid3d 1 個に集約する(BoolUnite / BoolSubtract)
  • 整合性チェックの誤差許容は 1 mm。不一致はエラー停止し、自動補正も再生成もしない
  • 基準の表で「−」のセルは null として扱い、0 に潰さない
  • 006 / 007 / 008 への参照を持たない。共通ロジックはコードとして移植する

部材間の整合チェック

統合版の利点として、同じ量を 2 部材が別々に入力している箇所を突き合わせる。 タイロッドの海側鋼管矢板径と前壁の外径、タイロッドの矢板ピッチと前壁の有効幅 B、 タイロッドの軸心標高と控え杭の Z_tr、タイロッドの span と控え杭の span。 いずれも 1 mm の許容で照合し、不一致は生成前に止める。

注意

使う前に知っておくこと

実機動作は未検証

開発機に AutoCAD 2025 / Civil 3D 2025 が入っていないため、Plugin 層はスタブによる 構文・型検証までしか行えていない。参照 DLL のバージョンも実測できておらず、 不一致は TypeLoadException / MissingMethodException として ランタイムでのみ顕在化する。実機で scripts/verify-dll-versions.ps1 が exit 0 になることを確認するまで配布しないこと。

積算基準に OCR から復元できなかった表がある

ジェット併用の噴射ノズル数・ジェット使用台数の表(3-16-16)は、原文のセル結合により どの数値がどのセルか特定できなかった。推測で埋めることはせず、利用者入力として受け取っている。 台数さえ決まれば発動発電機・水中ポンプ・水槽は自動決定されるため、原本の表を確認のうえ入力すること。

このほか、施工規模区分 E3 の係数表も崩れており、打撃工法と同じ「50 本未満 −0.05」と解釈して実装している。

帳票 CSV の列名は未検証

実際の積算ソフトのエクスポート形式(列名・並び順・エンコード)を確認できていないため、 業界の一般的な慣行を仮定して別名リストを組んである。実データが手に入り次第、 Core.Import 配下の各インポータに列名を追加すれば対応できる。 対応エンコードは UTF-8 のみ。

移植元 007 の継手質量にバグがある

JointCatalog.JointMassPerM は P-P 形で鋼管を 1 本分(34.7 kg/m)しか数えないが、 実形状は両側とも φ165.2×9 の鋼管であり、正しくは 69.4 kg/m。約 50% の過小評価になる。 009 では側別質量を持つ JointMass を新設して積算に用いており影響はないが、 007 側の修正は別途必要。

既存 FrontWall.DriveEstimate.GetLabor の労務工数にバグを確認

控え杭(4節 3-4.6)の労務工数を実装する過程で基準表を読み直した結果、前壁の打撃工法(3-4.5)と 共通のはずの労務表(交通誘導員・世話役・特殊作業員等)に既存コードとの不一致が見つかった。 基準は陸上打設で世話役=2 名(<20m)/3 名(≥20m)、特殊作業員=1 名/2 名だが、 既存の FrontWall.DriveEstimate.GetLabor は陸上を杭長によらず一律 2 名としており、 海上側も境界を 20m/25m の 3 段で判定する誤りを含む(正しくは 25m 一段のみ)。 新設した AnchorPile.AnchorDriveEstimate.GetLabor は正しい表で実装済み(テスト T1208 が同一入力で両者が食い違うことを明示的に確認している)。 既存の前壁側は「触れなければならない箇所だけ触れる」の方針により意図的に未修正のまま。 前壁の打撃工法積算を利用する際は労務工数の欄を手動で見直すこと。

控え杭の打設歩掛は陸上施工のみ対応

SPQW_ANCHORPILE_Estimate は 4節 3-4.6 のうち陸上施工の労務・仮設をもとに実装した。 海上施工(台船・引船が絡む区間)の歩掛はまだ組み込んでいない。

加重平均N値の算定は R・Sb・γ で除外ルールが異なり、岩盤の扱いは 009 独自判断

基準原文は R(極限支持力)用の N 平均を「表層から連続する N=0 の区間を除く」、 Sb(必要根入れ)用は「表層から連続する N≦5 の区間を除く」と明記するが、 γ(土質区分ごとの単位体積重量)に対応する N 平均の除外ルールは原文に記載がない。 Geotech.BoringLogAnalysis.CalcWeightedNBySoilType は除外なしの単純加重平均として実装している。 また、岩盤層(N 値でなく qu で評価する層)は R・Sb 双方の加重平均から常に除外しているが、 これは原文が岩盤混じり地層を明示的に想定していないための 009 独自の判断であり、 実務では地質状況に応じて手動確認すること。

そのほかの限定事項

  • 前壁の一括生成は直線配置のみ。平面線形が曲がる・折れる岸壁には対応しない
  • ジェット併用の γ は代表 1 層で算定する。互層の現場では Core の WeightedGamma を使うか、加重平均済みの値を入力する
  • ジェット併用の配管系部材・導材・拘束費は別代価表につき未実装
  • 鋼材質量の算定基礎が工法間で揃っていない。打撃は本管のみ、振動 2 種は本管 + 継手金物を使う(基準はどちらも「鋼材質量」としか書いていない)
  • 端数処理が既存モジュールと異なる。振動 2 種は基準どおりの四捨五入、既存の打撃は .NET 既定の銀行丸めのまま
  • 『港湾工事工種体系ツリー』への工種マッピングは未実装
  • CalcWeightedN と積算コマンドの自動連携は無い。算出値は各コマンドの加重平均N値欄へ手入力で転記する。また積算コマンドは R 用・Sb 用を区別せず単一の nAvg を両方の計算に使うため、両者が大きく異なる地盤では値の使い分けを利用者が判断すること
